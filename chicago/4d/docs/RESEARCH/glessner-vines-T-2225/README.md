# T-2225 — Selective July vines

Seven bounded planting areas add Boston ivy to the Prairie front and Virginia
creeper to the courtyard. They share one seeded layout in Full and Light, with
connected woody growth, original lobed/compound leaf profiles and green July
foliage. Full follows the actual masonry relief with stems, petioles and curled
leaves. Light uses the same original atlas on continuous masked panels.

## Evidence and reconstruction

The HABS written history transcribes the family's 1923 account of Virginia
creeper transplanted from the previous home in 1887, including a 55-foot vine,
and Boston ivy sent after Alpheus Hardy's June 1887 visit. The museum's courtyard
wall text corroborates growth on the south common-brick boundary since 1887.
Neither supplies a measured July 1904 coverage map. Taylor 9974 shows leafed-out
street trees and visible stonework, with an uncertain pre-1908 date; Taylor 2135
shows an earlier, bare-season house. These views do not justify a blanket of
later ivy or an exact summer courtyard layout. The Lowe stable attribution
remains disputed and is excluded.

The archived USDA NRCS Virginia-creeper guide supplies five compound leaflets,
toothed margins, mature green foliage and botanical size bounds. It supplies
no Glessner planting position or date. Its text gives inconsistent fruit timing,
so no conspicuous ripe berries were added for July 1. Boston profiles and all
atlas pixels are original procedural reconstructions. No unresolved-rights
photograph is traced, sampled or embedded.

`form.vines` remains textual history with its existing source-rights limitations.
The consumed numeric record is the separately declared reconstructed
`form.vines_details`, supported by cleared HABS geometry and public-domain USDA
botanical bounds. L-glessner-vines-2225 records placement, maintenance, density,
branch trajectories, leaf shapes, colors, wall offsets and Light's depth
approximation. Existing district trees are retained.

## Geometry and material checks

All plants start at a shared buried root. Duplicate shared petiole tubes are
suppressed. Leaf polygons and branch paths exclude actual door/window rectangles
and their 220 mm clear surrounds; no planting covers the unresolved tower or
roof junctions. A spatial index of outward-facing masonry provides stem contact
and conservative support for curled leaves. Light panels share depth vertices,
so their boundaries cannot step apart.

The original 4096 × 2048 RGBA atlas is generated by
`tools/generate_glessner_vines.py`; its check compares decoded pixels, independent
of PNG compressor versions. Both canonical tiers export MASK alpha at cutoff
0.5. The Light stone-occlusion bake uses the same masked shader, with the exported
UV orientation restored. Its cache includes the atlas and foliage UV hashes.
A separate actual Cycles experiment measured mean open-mask occlusion 1.0 against
0.0094 for an opaque card: invisible panel rectangles must not darken the stone.

The component gate exercises actual shared geometry, connected growth, duplicate
and degenerate triangles, raised masonry contact, opening clearances, Light
panel continuity, matched layouts and absence from earlier building profiles.
The fixture's 55,836 Full triangles are a test measurement, not the canonical
house total. Canonical counts and browser costs are recorded below after baking.

The first canonical bake was rejected: K01 found 1,488 coincident Full faces,
all in the woody petioles. Compound leaflets shared a base but selected slightly
different masonry support depths, producing nested stalks. The generator now
uses one maximum support junction per compound leaf and one shared stalk.
The expanded fixture uses a finely tessellated, gently sloped wall: the previous
algorithm reproduces the 1 mm coincidence failure and the corrected algorithm
passes. The original raw duplicate/degeneracy tests remain. No geometry gate or
measurement quantum was relaxed; the rejected bake is not the shipped asset.

The second bake passed K01 but was rejected in the actual browser close-up:
all 34,212 Full leaf triangles had constant face normals, so the curled leaves
read as angular paper fans. Full now supplies shared, unit corner normals across
each fan through the existing exporter path. This changes shading without adding
triangles, moving a leaf or changing the atlas. The original ten captures are
retained as the rejected visual version; final acceptance uses fresh captures of
the revised export. Confidence screenshots reuse the measured west-court stand,
where the vine stays inside both desktop and phone crops; the five measured
before/after cameras and their budget assertions are unchanged.

passing scale, origin and metric UV checks. Both tiers retain MASK alpha at 0.5
and double-sided original foliage. The fixed-camera browser records below include
all scene geometry, lighting and shadows, using normal published /1904/ boot.

## Writer registration repair

The first full preflight identified a missing writer-inventory row for the new
atlas generator. Its bare write mode was then measured twice in a clean isolated
Git fixture containing the actual current modules, numeric input and candidate
atlas. Both runs rewrote the output with the same SHA-256 and no Git changes; a
deliberately perturbed output was restored. The measured inventory row now records
that result and its explicit pre-bake ordering requirement. The application
checkout itself was not claimed clean by this experiment. No atlas, geometry,
camera, budget or assertion changed for this registration repair. A fresh full
preflight is required before commit and PR creation.
